## 1. 结论摘要

**一句话**：YesPlayMusic 是一个 **Vue 2 + Electron 13 + Webpack 4** 的纯 JavaScript 单仓应用，架构清晰但整条工具链已落后主流 3～5 年（Vue 2 已停止维护、Electron 13 存在已知安全问题、无任何测试）；它以「内嵌 Node.js API 服务 + 渲染进程直接调用」的方式绕开了跨域与后端部署，这是它最值得继承的设计。

### 核心事实

| 维度 | 事实 |
|---|---|
| 基线版本 | YesPlayMusic `0.4.11`，MIT 协议，官方已进入维护模式（新功能转向 2.0 Alpha） |
| 语言 | 纯 JavaScript（无 TypeScript），仅用 JSDoc 做类型提示 |
| 前端 | Vue `2.6.11` + Vue Router `3.4.3` + Vuex `3.4.0` + vue-i18n `8.22.0`，无 UI 组件库（全手写 SCSS + CSS 变量主题） |
| 构建 | `@vue/cli-service` `~4.5`（Webpack 4）+ Babel + Sass，另用 esbuild `0.20.1` 给 `node_modules` 做 ES2015 降级 |
| 桌面 | Electron `13.6.7` + vue-cli-plugin-electron-builder `2.1.1` + electron-builder `23` |
| 音频 | Howler.js `2.2.3`（`html5: true`，mp3/flac） |
| 本地存储 | localStorage（设置）+ Dexie `3.0.3`/IndexedDB（歌曲缓存与元数据）+ electron-store `8`（窗口/代理） |
| 后端 | 内嵌 `@neteaseapireborn/api` `4.29.7`，监听 `127.0.0.1:10754`，白名单注入 124 个接口模块 |
| 歌词 | 行级 LRC（含翻译/罗马音），**无逐字歌词** |
| 测试 | **完全没有任何测试**（无测试框架依赖、无 test 目录） |
| 运行环境 | Node `14 || 16`（`.nvmrc` = 14），CI 用 Node 16 |

### 关键判断

1. **架构值得继承，工具链必须升级。** 应用分层（views / components / store / api / utils / electron）职责清晰，`Player.js` 单例 + Vuex Proxy 持久化的设计很巧妙；但 Vue 2 已于 2023 年底停止维护，Webpack 4 + Electron 13 组合难以承接新的歌词渲染（TTML 逐字）与图形化需求（WebGL/WebGPU）。
2. **歌词能力是当前最大的产品短板，也正好是手上资源最齐的方向。** 工作区内的 `amll-ttml-db`（3K+ 首逐字歌词数据）与 `folia-major`（成熟的多模式歌词可视化实现）已经给出了完整答案，而 YesPlayMusic 仍停留在行级 LRC。
3. **`folia-major` 是 AGPL-3.0，与 MIT 的 YesPlayMusic 不兼容。** 它可以作为架构与交互的参考，但**不能直接复制代码进 MIT 项目**，否则将被迫整体 AGPL 化（详见 [4.3](#43-folia-major) 与 [5.4](#54-关键风险与应对)）。
4. **「一起听」功能有现成的、代价极低的实现路径。** `YesPlayMusic-listen-together-support` 用纯 HTTP 轮询实现了网易云官方房间协议，不需要任何自建后端——但它依赖上游 API 包中**实际不存在的 5 个 multi-room 模块**，存在明确的坑（详见 [4.4](#44-yesplaymusic-listen-together-support)）。
5. **安全配置严重过时。** `nodeIntegration: true` + `contextIsolation: false` + `webSecurity: false` 的组合意味着渲染进程拥有完整 Node 权限，一旦有 XSS 即等同任意代码执行。这在二次开发中应优先改造。

**值得注意的两个设计：**

1. **`Player` 单例 + Proxy 自动持久化**（`src/store/index.js:56-67`）——播放器实例被 `Proxy` 包裹，任何 `set` 操作都会自动触发 `saveSelfToLocalStorage()` 与 `sendSelfToIpcMain()`，因此播放状态无需显式保存逻辑即可落盘到 localStorage 并同步给主进程（托盘/MPRIS）。这个设计在二次开发中值得保留。
2. **渐进式类型提示**：虽然没有 TypeScript，但关键模块（`Player.js`、`lyrics.js`、`api/*.js`）使用了完整的 JSDoc 标注（`@typedef`、`@returns {ParsedLyric[]}`），配合 `jsconfig.json` 提供 IDE 补全。这为后续迁移 TS 降低了成本。

### 3.5 Electron 桌面外壳

**主进程结构**：`package.json` 的 `"main": "background.js"` → `src/background.js`（493 行）。核心是一个 `Background` 类，在 `init()` 中按序完成：

1. `app.requestSingleInstanceLock()` 单实例锁
2. 启动内嵌网易云 API（`startNeteaseMusicApi()`）
3. 创建 express 服务器（`127.0.0.1:27232`）
4. 注册 `app://` 特权协议
5. `app.on('ready')` → 创建窗口 → 托盘 → IPC → 代理 → 自动更新 → 菜单 → Dock 菜单 → Touch Bar → 全局快捷键 → OSDLyrics → MPRIS

**`src/electron/` 模块一览**：

| 文件 | 行数 | 职责 |
|---|---|---|
| `ipcMain.js` | 326 | 主进程 IPC 处理器：`unblock-music`（原生音源解锁）、窗口控制、设置同步、Discord RPC、代理设置、快捷键管理、托盘事件转发 |
| `ipcRenderer.js` | 94 | 渲染进程 IPC 监听：`changeRouteTo`/`play`/`next`/`previous`/`like`/`repeat`/`shuffle`/`increaseVolume`/`setPosition` 等 14 个通道 |
| `menu.js` | 220 | 应用菜单（含快捷键编辑） |
| `tray.js` | 282 | 系统托盘（Windows/Linux） |
| `mpris.js` | 118 | Linux D-Bus MPRIS 媒体控制（`mpris-service` `2.1.2`），另含 `createDbus` 用于 OSDLyrics |
| `touchBar.js` | 81 | macOS Touch Bar 歌词显示 |
| `dockMenu.js` / `globalShortcut.js` | — / 58 | macOS Dock 菜单；全局快捷键注册 |
| `scrobble.js` | 161 | **内嵌 API 的自定义补丁**：因网易云已不再统计旧的 weapi `/feedback/weblog` 上报，改为直接构造 clientlog 域名的 **eapi** 请求（先 `startplay` 进"最近播放"，再 `play` 累计"听歌排行"），复用 `@neteaseapireborn/api/util/crypto` 的加密能力 |

**窗口安全配置（重要）**：

```js
webPreferences: {
  webSecurity: false,        // ⚠ 关闭同源策略
  nodeIntegration: true,     // ⚠ 渲染进程拥有完整 Node 权限
  enableRemoteModule: true,  // ⚠ Electron 12+ 已弃用的 remote 模块
  contextIsolation: false,   // ⚠ 关闭上下文隔离
}
```

同时窗口使用 `titleBarStyle: 'hiddenInset'`（macOS）/ `frame: false`（Windows/Linux 自定义标题栏），窗口尺寸与位置通过 `electron-store` 持久化，并对多显示器场景做了位置有效性校验（`background.js:205-242`）。

**双端口设计**：主进程内同时跑两个 HTTP 服务——`10754` 是网易云 API，`27232` 是 express（静态资源 + `/api` 反代到 10754 + `/player` 查询当前播放状态）。生产环境窗口加载 `http://localhost:27232`，URL 使用 `app://` 协议。`/player` 接口通过 `executeJavaScript('window.yesplaymusic.player')` 直接把真实播放器对象序列化返回，可被外部工具（如 OBS 插件、状态栏小部件）消费——这是一个很有价值的可扩展点。

### 3.6 音频播放引擎

核心：`src/utils/Player.js`（**1010 行**），一个以 `Howler` 为底层的类，实例被 Proxy 包裹后挂到 `store.state.player`。

**播放状态模型**：

| 字段 | 说明 |
|---|---|
| `_list` / `_shuffledList` | 原始播放列表 / 随机打乱后的列表（随机模式下 `list` getter 返回后者） |
| `_current` / `_shuffledCurrent` | 对应两个列表的下标 |
| `_repeatMode` | `off` / `on`（列表循环）/ `one`（单曲循环） |
| `_reversed` | 倒序播放开关 |
| `_playNextList` | 插播队列，非空时优先播放（优先级高于正常顺序） |
| `_isPersonalFM` / `_personalFMTrack` / `_personalFMNextTrack` | 私人 FM 模式与预取缓存 |

**音源获取优先级**（`_getAudioSource`，`Player.js:494-502`）——这是全项目最核心的降级链：

```
① IndexedDB 缓存（getTrackSource）
   ↓ 未命中
② 网易云官方 /song/url（仅登录态）
   · br 参数由 settings.musicQuality 决定（'flac' → 350000）
   · freeTrialInfo !== null 的试听曲直接判为不可播放并跳过
   · 若开启「自动缓存歌曲」则落库
   ↓ 失败
③ UnblockNeteaseMusic（仅 Electron 且开关开启）
   · 经 IPC 调用 Rust 原生模块，默认音源 ['ytdl','bilibili','pyncm','kugou']
   · bilibili 音源返回 base64，需转 Blob URL
   ↓ 全部失败
④ showToast「无法播放 XXX」并按 UNPLAYABLE_CONDITION 跳到下一首/上一首
```

> 未登录（`isAccountLoggedIn()` 为假）时直接返回 `https://music.163.com/song/media/outer/url?id=<id>`，这是网页版外链播放路径。

**其它值得注意的细节**：

- `html5: true` —— Howler 使用 `<audio>` 元素而非 Web Audio，因此**目前无法直接接入 Web Audio 频谱分析**（若要做可视化需要改造为 `AudioContext` + `MediaElementSource`，folia-major 正是这么做的）。
- 音频错误按 `MediaError.code` 分流：`3`（解码错误）与 `4`（格式不支持）跳下一首，其它错误（如网络中断）会重新获取音源并恢复到原进度继续播放（`Player.js:353-375`）。
- 播放/暂停用 200ms 淡入淡出（`PLAY_PAUSE_FADE_DURATION`）避免爆音。
- `_cacheNextTrack()` 在切歌时预取下一首的音源，私人 FM 也会预取下一首曲目，形成"预热"管道。
- `setOutputDevice()` 直接操作 Howler 内部私有字段 `_sounds[0]._node.setSinkId(...)` —— 依赖 Howler 内部实现，升级 Howler 时有破坏风险。
- 进度同步依赖 `setInterval` 每秒回写 `_progress` 到 localStorage（key `playerCurrentTrackTime`），代码注释中作者自己标注了这里存在竞态 bug（`Player.js:249-251`）。

### 3.7 数据持久化与缓存

三层存储，职责明确：

| 层 | 技术 | 存储内容 | 位置 |
|---|---|---|---|
| 设置与用户数据 | **localStorage** | `settings`（全部设置项）、`data`（用户信息/关注列表等）、`player`（播放器状态）、`lastfm`、`appVersion` | 由 Vuex 插件 `plugins/localStorage.js` 只持久化 `settings` 与 `data` 两个 key；`player` 由 Player 实例自行写入 |
| 歌曲内容缓存 | **Dexie 3.0.3 → IndexedDB** | 库名 `yesplaymusic`。`trackSources`（音频二进制，含 `bitRate`/`from`/`createTime`）、`trackDetail`（歌曲详情+权限）、`lyric`、`album` | `src/utils/db.js`（223 行），schema 演进到 version 4 |
| 主进程配置 | **electron-store 8** | 窗口 `width`/`height`/`x`/`y`、`proxy`、`settings` 副本 | `background.js` 中 `new Store(...)` |

**缓存淘汰策略**（`db.js:73-91`）：模块加载时先 `initTracksCacheBytes()` 全量统计已缓存字节数（带 5 秒轮询等待 settings 就绪），超过 `settings.cacheLimit`（MB）时按 `createTime` **最旧优先**逐个删除，直至低于阈值。`cacheTrackSource` 在缓存音频的同时还会以 `axios.get` 预请求封面的 512/224/1024 三个尺寸（利用浏览器 HTTP 缓存加速 UI）。

**DB 重置**：`window.resetApp()`（`main.js:15-24`）清空 localStorage、IndexedDB、Cookie —— 排查问题时的兜底手段，二次开发中应保留。

### 3.8 API 层与内嵌服务端

**这是一个"自带后端"的架构**，也是 YesPlayMusic 最省心的设计：

```
渲染进程 axios
   │  baseURL: Web → /api（需外部 API 服务，vercel.example.json / Dockerfile 提供）
   │           Electron 生产 → VUE_APP_ELECTRON_API_URL = /api（经 express 27232 反代）
   │           Electron 开发 → VUE_APP_ELECTRON_API_URL_DEV = http://127.0.0.1:10754（直连）
   ▼
主进程内嵌 @neteaseapireborn/api 4.29.7 @ 127.0.0.1:10754
   │  启动方式：server.serveNcmApi({ port: 10754, moduleDefs: require('../ncmModDef') })
   ▼
网易云音乐官方接口
```

**`src/ncmModDef.js`（622 行）** 是接口白名单：以 `{ identifier, route, module }` 三元组显式声明 **124 个** 接口模块，覆盖 user(18) / playlist(24) / artist(15) / album(11) / mv(7) / login(8) / top(9) / song(3) / cloud(4) 等。**裁剪接口只需删条目**，这比直接暴露整个 API 包更安全可控，也为替换成 `api-enhanced` 提供了清晰的改造点。

**axios 拦截器**（`src/utils/request.js`）承担的横切逻辑：

- **请求**：注入 `cookie`（Web 端从 `js-cookie` 读 `MUSIC_U`）、`realIP`（可配置，用于绕过地域限制）、`proxy`；非 Electron 且非登录接口时**硬编码 `realIP = 211.161.244.70`**
- **响应**：`code === 301 && msg === '需要登录'` 时自动 `doLogout()` 并跳转登录页；响应体直接透传（`return res`，不做 `data` 解包）

**前端 `src/api/` 目录**按领域封装了 9 个文件（`album` / `artist` / `auth` / `lastfm` / `mv` / `others` / `playlist` / `track` / `user`），每个函数都有完整的中文 JSDoc 说明参数含义。

**登录方式**：扫码（`qrcode` 生成 + 轮询 check）/ 手机验证码 / 邮箱账号密码（md5 加密 + `crypto-js`），凭据以 Cookie 形式保存，`utils/auth.js` 提供 `isAccountLoggedIn()` / `isLooseLoggedIn()` 两档判断。

### 3.9 歌词系统现状

**这是 Aki Music 最需要升级的部分。**

当前实现：

**能力缺口**：

### 3.10 音源解锁（UnblockNeteaseMusic）

- **依赖**：`@unblockneteasemusic/rust-napi` `0.4.0`（Rust 编写的原生 Node 扩展，性能优于原 JS 版）
- **集成点**：主进程 `ipcMain.handle('unblock-music', ...)`（`src/electron/ipcMain.js:141-199`），渲染进程通过 `ipcRenderer.invoke` 调用
- **执行流程**：`new UNM.Executor()` → `executor.list()` 取可用音源 → `search(sourceList, song, context)` 匹配 → `retrieve(matchedAudio, context)` 取音频
- **默认音源**：`['ytdl', 'bilibili', 'pyncm', 'kugou']`；bilibili 返回的音频需转 base64 → Blob URL（且主进程侧带 `Referer: https://www.bilibili.com/` 头）
- **可配置项**（`store.state.settings`）：`unmSource`、`unmEnableFlac`、`unmProxyUri`、`unmSearchMode`（`fast-first`/`order-first`）、`unmJooxCookie`、`unmQQCookie`、`unmYtDlExe`
- **打包要求**：`vue.config.js` 中 `electronBuilder.externals: ['@unblockneteasemusic/rust-napi']`，确保 `.node` 二进制不被 webpack 处理；CI 中还有一步 `get_unm_version` 读取已安装的 UNM 版本
- **限制**：**Web 版不支持**（`process.env.IS_ELECTRON !== true` 直接返回 null），仅桌面端可用

| **依赖零变化** | `package.json` 的依赖与 devDependencies **与上游完全一致**，功能完全构建在既有 `@neteaseapireborn/api` 之上 |

**技术机制**（这是它最有价值的部分）：

- **传输层：纯 HTTP 轮询网易云官方接口，无 WebSocket、无第三方服务、无自建后端。** 代码注释明确说明官方实时通道是网易云 IM（云信 NIM）聊天室推送，需要原生 `accid/token` 凭据，因此**刻意不实现**，改用轮询。
- **轮询节奏**：心跳 20 秒（双人房）/ 8 秒（多人房，同时携带权威队列 `roomSongInfo`）；成员状态 15 秒；播放/歌单同步 4 秒。
- **房间模式**：双人房（创建/分享链接/接受邀请，支持播放列表 REPLACE 同步）与**多人房「围坐听歌」**（`multi/match/ack` 加入，服务端返回权威队列，客户端自动跟随；`SONG_UP` 置顶，但不能直接切歌——协议限制 `SONG_SWITCH` 只作用于队首）。
- **同步状态**：当前曲目 ID、播放状态（PLAY/PAUSE）、进度（ms）、播放/暂停/跳转指令（带 `clientSeq`）、房间歌单（整表 REPLACE + 递增 `version`）、成员列表、多人房权威队列。
- **防回环设计**（工程质量较高）：忽略自身 `clientSeq` 与自身 `userId` 的回声；用 `serverSeq|clientSeq|songId|progress|status` 签名去重；**20 秒 `_remoteSuppressUntil` 抑制窗口**防止跟随/上报互相触发；进度仅在落后 >5 秒时向前对齐；房间丢失仅通过心跳 code 488 判定；手动切歌有 20 秒用户覆盖窗口。
- **分享链接兼容**：支持 `st.music.163.com/listen-together/share/?...`、`.../multishare/index.html?...`、`orpheus://nm/play/listenTogether?...` 以及裸 `roomId:inviterId` 四种格式。
- **接口路由**：在 `ncmModDef.js` 中新增 14 条注册（`/listentogether/room/*`、`/heatbeat`（原文拼写如此）、`/play/command/report`、`/sync/playlist/get`、`/multi/match/*` 等）。

**⚠️ 两个必须知道的坑**：

1. **多人房功能实际跑不起来。** `ncmModDef.js` 会 `require` 五个 `@neteaseapireborn/api/module/listentogether_multi_match_*` 模块，但对 4.29.7～4.29.13 各版本 tarball 的检查显示：**这些文件在发布包中根本不存在**（4.29.10 之后甚至是约 1 KB 的占位包）。由于 require 在 API 服务启动时执行，多房间相关路由会导致启动报错——而 `background.js` 只在 `startup.log` 里记录，不弹窗，属于**静默失败**。要真正启用多人房，必须自行向 API 包补写这 5 个模块。
2. **改动中含非功能性的版本漂移。** 部分"修改"文件（`mpris.js`、`tray.js`、`touchBar.js`、`views/lyrics.vue`、`dailyTracks.vue`、`settings.vue`）只是 0.4.10 与 0.4.11 的差异，并非功能改动，合并到 0.4.11 基线时需甄别。

> **对 Aki Music 的意义**：这是**成本最低的特色功能来源**——双人房（`listentogether_*` 九个模块）在 4.29.7 中是齐全的，可直接移植；多人房需要补 API 模块，属于中等工作量。整个方案不需要服务器，非常适合个人项目。
