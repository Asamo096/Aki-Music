## 0. 一页结论

- **路线**：先做「音频反应总线」这一层基础设施，再移植 **fume** 作为唯一旗舰模式，最后做低成本观感打磨。装饰性的全屏频谱条、tempera / sonnet / diorama / cappella 一律不做。
- **一个关键事实**：fume 在 Folia 里是 **Canvas 2D** 实现（`useFumeCanvasStage.ts` 注释明确写了：Pixi 版本实测 CPU 不省、显存多 85 MiB，因此被弃用）。本计划**不为 fume 引入 Pixi**；Canvas 2D 也更适合我们常驻的歌词页。
- **工作量**：核心 V0–V3 约 **9–16 人日**；可选的 still 约 0.5–1 人日；claddagh / monet 各 4–8 人日，建议下一轮再评估。
- **最大风险**：远程音源接不上 Web Audio（跨域会变哑）。对策：**只对同源 blob 建 `AnalyserNode`；远程音源改用 `captureStream()`，失败就回退纯视觉呼吸**——任何情况下都不影响播放本身。
- **进度（2026-11-20）**：**V0 + V1 已完成**；**V2 首版（fume）已可切换使用**（Canvas 2D 竖向歌词流 + 逐字打印 + 节拍粒子），缓存音源实测可用、远程音源按设计回退。细节见 §8。

### 1.2 缺口

| 缺口 | 影响 |
|---|---|
| 没有音频分析（当前 `new Howl({ html5: true })`，没有 Web Audio 图） | 背景与歌词只能做固定节奏的呼吸/漂移，无法跟鼓点 |
| 没有视觉模式注册表与运行时 | 无法安装第二个歌词呈现模式，也没有统一的帧循环/质量档/销毁契约 |
| 没有 Canvas 文本渲染层 | 无法承载 Folia 式「逐字打印」等 Canvas 模式 |
| 没有质量档与减少动态效果开关 | 高性能机器与省电场景无法兼顾 |

### 1.3 目标 / 非目标

**目标**

1. 音频能量驱动**现有**背景与歌词发光（运动速度、亮度、强度），且只驱动运动、不驱动色相；
2. 提供 1 个 Folia 派生的旗舰模式（fume），观感对齐 Folia，歌词仍是主体；
3. 建立模式注册表、统一运行时、质量档、`prefers-reduced-motion` 支持；
4. 所有阶段可独立交付、可随时回退（关闭开关即回到当前歌词页）。

**非目标**

- 不搬 React / framer-motion / R3F，不引入 Pixi（除非未来移植 monet/sonnet 时单独评估）；
- 不做 tempera（121 种分镜）、sonnet、diorama、cappella；
- 不做装饰性「全屏频谱条 / 圆形均衡器」；
- 桌面歌词与远程窗不跑重特效（壁纸层功耗优先）；
- 不接 AI 情感主题（延续 D9：离线封面取色）。

### 2.1 音频总线 `src/visual/audioBus.ts`

**音源分类与接入矩阵**

| 音源 | 形态 | 接入方式 | 风险 |
|---|---|---|---|
| 缓存/本地 | `blob:`（`_getAudioSourceBlobURL`） | `AudioContext` → `createMediaElementSource(el)` → `AnalyserNode` → `destination` | 低。同源，音质/音量语义不变（元素 volume 仍然生效） |
| 官方远程 | `http(s)://m*.music.126.net/...` | **不改路由**，用 `el.captureStream()` → `createMediaStreamSource` → analyser | 中。若拿不到音轨或数据恒为 0 → 回退视觉呼吸；播放不受影响 |
| UNM/第三方 | 远程 URL（可能无 CORS） | 同上（captureStream 优先；失败回退） | 中。绝不使用 `createMediaElementSource` 重路由，避免静音 |

**关键约束**

1. `createMediaElementSource` 对同一元素只能调用一次，且一旦调用就把元素从默认输出摘除——**只允许对同源 blob 使用**，并必须同时接到 `destination`；
2. AudioContext 懒创建（首次播放时），`resume()` 绑定用户手势；
3. 每个 Howl 切换时（`Howler.unload()`）释放旧的 source/analyser 连接，不关闭共享 context；
4. 帧率：分析循环与视觉渲染共用一个 rAF（默认 30Hz，质量档高时 60Hz）；窗口隐藏/最小化时停止。

**信号处理（移植 Folia 参数）**

```text
fftSize = 2048, smoothingTimeConstant = 0.6
bass 20–150Hz / lowMid 150–400 / mid 400–1200 / vocal 1000–3500 / treble 3500–12000
value' = (value/255)^boost * 255        // boost: power 3, bass 1.8, lowMid/mid/treble 2, vocal 1.5
平滑：起音 60ms，释放 250ms（一阶低通）
暂停/无信号：使用 0..40 的“呼吸值”，不是 0（避免背景死掉）
```

**对外接口**

```ts
type AudioFrame = {
  power: number; // 0..255
  bands: { bass; lowMid; mid; vocal; treble }; // 0..255
  active: boolean; // 是否真的有信号
  updatedAt: number;
};
audioBus.subscribe(cb: (frame: AudioFrame) => void): () => void;
audioBus.getFrame(): AudioFrame;
```

**V0 先做一次技术验证（0.5 天，阻塞后续）**

1. 缓存音源：接 analyser 后确认有声、能量随音乐变化、暂停时衰减；
2. 官方远程：`captureStream()` 是否有 audio track、是否有非零数据；
3. UNM 音源：同上；
4. 结论写回本文件「实测记录」，再决定 V1 是否覆盖全部音源。

### 2.2 视觉运行时 `src/visual/runtime.ts`

- **单 rAF**：全局一个循环，所有订阅者按注册顺序执行；禁止模式各自 `requestAnimationFrame`。
- **可见性**：`document.hidden`、`app` 切走、歌词页 `showLyrics === false`、副窗口 → 停止渲染（模式 `pause()`）。
- **质量档**（`settings.visualQuality`）：

| 档位 | 帧率 | DPR 上限 | 附加效果 |
|---|---|---|---|
| `high` | 60 | 2 | 全效果 |
| `balanced`（默认） | 40 | 1.5 | 关闭大半径模糊，保留发光 |
| `low` | 24 | 1 | 关闭发光/粒子，静态排版 |

- **减少动态效果**：`prefers-reduced-motion` 或设置项 → 运动冻结为静态帧，歌词进度仍更新。
- **销毁契约**：`mount(container, ctx) → { destroy(): void }`；切换模式、离开歌词页、隐藏超过 30 秒都调用；验收以「切换 50 次内存漂移」为准。

### 2.3 模式注册表 `src/visual/modes/registry.ts`

```ts
type VisualModeEntry = {
  id: 'off' | 'fume' | 'still' | 'claddagh' | 'monet';
  labelKey: string;            // locale: settings.visual.modes.*
  cost: 'low' | 'medium' | 'high';
  load: () => Promise<VisualModeModule>; // 懒加载，主包不引入
};
```

- `settings.visualMode` 默认 `'off'`（当前歌词页原样工作，零回归）；
- 模式模块只接收**共享契约**，不直接读 store、不解析歌词、不管理播放。

### 2.4 歌词输入契约（共享，禁止复制）

模式接收：

| 字段 | 来源 | 说明 |
|---|---|---|
| `data: LyricData` | 歌词页现有请求链 | 行/词/翻译 |
| `getTime(): number` | `createLyricPlayhead` | 当前播放秒数（与歌词页/桌面歌词同一套节奏） |
| `theme` | `coverTheme` | 主色/辅色/深色主题/情绪档 |
| `audio: AudioFrame` | audioBus | V1 之后可用 |
| `quality / reduceMotion / intensity` | settings | 运行时由 Host 传入 |
| `fontStack` | `fontStacks.ts` | Canvas 与 DOM 使用同一字体栈 |

### 2.5 设置与 i18n

新增字段（`initLocalStorage.settings`，旧数据靠默认值合并，无需迁移代码）：

```js
visualMode: 'off',          // off | fume | still | ...
visualQuality: 'balanced',  // high | balanced | low
visualAudioReactive: true,  // 音频反应开关
visualIntensity: 0.6,       // 0..1，背景/发光强度
visualReduceMotion: false,
```

设置页新增「视觉」分区：模式选择（含成本标注）、质量档、音频反应、强度滑杆、减少动态效果。
locale 四个语言（zh-CN / zh-TW / en / tr）补 `settings.visual.*`。

### 2.6 边界

- 桌面歌词窗 / 远程窗只消费现有快照，视觉深化不改变 IPC 契约；
- 歌词页常驻（`App.vue` 里 `v-show`），所以运行时必须在不可见时**真正停止**；
- 切歌、切模式不重建 AudioContext；不重复创建 MediaElementSource。

## 3. 阶段计划

### V0 基础层（2–4 人日）

**交付**

- `src/visual/audioBus.ts` + 纯函数（频段、幂压缩、平滑）与单测；
- `src/visual/runtime.ts`（单 rAF、可见性、质量档）；
- 模式注册表 + `VisualizerHost.vue` 空壳（先只支持 `off`）；
- 设置字段、设置页分区、i18n、质量档接入；
- 技术验证报告（2.1 的 4 条）。

**验收**

- 歌曲播放时 `audioBus.getFrame()` 能在 blob 音源上读到非零能量；暂停 300ms 内衰减到呼吸值；
- 远程/UNM 音源若不可分析，`active=false` 且播放**无任何异常**（不断音、不静音）；
- 隐藏歌词页后 rAF 计数为 0；恢复后正常；
- 156 项既有单测 + 新增纯函数单测全部通过。

### V1 现有背景与歌词的音频反应（1–2 人日）

**交付**

- `LyricsBackgroundFluid.vue`：色块速度/尺度/亮度由 `power/bass` 驱动（CSS 变量，~15Hz 更新，只用 transform/opacity）；
- `LyricLines.vue`：当前行发光强度随 `vocal` 变化（有上限，低质量档关闭）；
- 设置里的「音频反应」「强度」生效。

**验收**

- 播放/暂停/静音的能量变化肉眼可见；暂停后 300ms 内回到呼吸；
- 1080p 下音频总线 CPU < 3%；歌词页整体不出现掉帧（DevTools Performance 抽查）；
- 关闭音频反应后与改造前**逐字节一致**（视觉回归对照截图）。

### V2 fume 模式（4–7 人日）

**交付**

- `src/visual/modes/fume/`：Canvas 2D 舞台（参考 Folia `useFumeCanvasStage.ts` / `fumeStage.ts` / `fumeBlockFrame.ts` / `fumeCameraStep.ts` / `fumeCanvasText.ts` / `fumeTextMeasure.ts` / `FumeBackground.ts` / `fumeTypes.ts`）；
- 文本测量：优先引入 `@chenglou/pretext`（MIT，v1.0；Folia 用 ^0.0.9，先做 API 兼容验证），不可用则退回 Canvas `measureText`；
- 静态块快照（已唱/未唱）与 15 秒空闲回收；打印中块使用 bounded raster（对齐 Folia 的 glyph cache 处理）；
- 音频响应：块发光/粒子能量取 `bass/mid/treble`；
- 字体栈、翻译、逐字进度、CJK 混排、自定义字体全部沿用现有输入。

**首版已实现（2026-11-20）**

| 文件 | 内容 |
|---|---|
| `src/visual/fume/layout.ts` | 换行（CJK/拉丁）、行块高度、相机目标、命中测试、逐字/整行进度；7 个单测 |
| `src/visual/fume/renderer.ts` | 单 Canvas 2D：竖向歌词流、逐字裁剪揭示、当前行发光、节拍粒子、主题压暗/提亮 + 文字列柔和底色、点击命中回传 |
| `src/components/FumeVisualizer.vue` | Vue 外壳：订阅共享 rAF、字体/字号/翻译/主题/音源响应、ResizeObserver、销毁时释放 |
| `src/views/lyrics.vue` | `visualMode==='fume'` 时用 Canvas 接管整页（隐藏 DOM 歌词/封面），点击某行可 seek |
| 设置 | `settings.visualMode`（off/fume）+ 设置页「歌词呈现模式」+ 四语言文案 |

首版实测：单帧绘制 1–2.4ms（Canvas 2D，无 WebGL），切模式/隐藏页面后 canvas 与调试句柄均被回收；打包版均衡档实测 **36fps**、单帧 0.7ms，点击歌词行 seek 正常。
与 Folia 的 fume 相比是**简化版**：不做 article-level 布局 / pretext 分段测量 / 静态块快照，逐字用片段裁剪揭示而不是逐字定位；后续按 §3 的打磨项继续。

**验收**

- 1080p、默认质量档 ≥ 55fps（采样 60 秒），掉帧 < 5%；
- 当前行切换与歌词页误差 ≤ 100ms；逐字进度与现有 `LyricLines` 对照 ±50ms；
- 播放 30 分钟，渲染进程内存漂移 ≤ 100MB；切换模式 50 次 ≤ 50MB 且无纹理泄漏；
- 中文/英文/日文混排、翻译开关、5 个预设字体 + 1 个上传字体均正常；
- 关闭模式立即回到现有歌词页，无残留 canvas / rAF / AudioNode。

### V3 观感打磨（2–3 人日）

- 切歌调色板插值（300–500ms）：色块颜色从旧主题过渡到新主题，不是瞬切；
- 逐字发光与「已唱/未唱」对比度对齐 Folia 的 `wordGlow` / `wordColoring`（只调参数，不改计时）；
- 背景情绪档从封面扩展到歌词密度（离线统计每行字数/语速），仍不接 LLM；
- 桌面歌词新增「描边 / 柔光」两档低成本预设（壁纸层不跑粒子/模糊）。

**验收**：切歌颜色无跳变（录屏比对）；四语言界面文案完整；桌面歌词 CPU 增幅 < 1%。

### V4 可选模式（按需）

| 模式 | 技术 | 工作量 | 说明 |
|---|---|---|---|
| `still` 极简 | DOM/Canvas | 0.5–1 | 无背景、纯排版，作为省电档顺带交付 |

## 5. 风险登记

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| R1 | 远程音源接 Web Audio 后变哑 | 中 | 高 | 远程**不**用 `createMediaElementSource`；只用 `captureStream`，失败回退呼吸；V0 先验证三类音源 |
| R2 | Canvas 文字发光开销大 | 中 | 中 | 沿用 Folia 的 glow 量化 + 静态块快照；质量档低时关闭发光 |
| R3 | pretext API 版本差异 | 中 | 中 | 固定版本 + V2 首日兼容 spike；失败则 `measureText` |
| R4 | 歌词页常驻导致泄漏 | 中 | 高 | 统一 mount/destroy 契约；隐藏即停；50 次切换验收 |
| R5 | 4K/高 DPI 性能 | 中 | 中 | DPR 上限 2；质量档自动降级 |
| R6 | 模式切换卡顿 | 低 | 中 | 空闲时预加载 chunk；旧模式保持到新模式就绪 |
| R7 | 自绘文本与 DOM 歌词观感不一致 | 中 | 中 | 共享字体栈与 renderHints；逐帧对照验收 |
| R8 | 许可证遗漏 | 低 | 高 | 新增移植文件逐个登记 NOTICE；AGPL 兼容 |

**实测踩到的三个坑（全部已修，后续移植模式时不要再踩）**

1. **Howler 复用 html5 音频元素**：`Howler` 的 Audio 池会复用元素，而 `createMediaElementSource` 对同一元素只能调用一次；一旦复用就会抛错、分析永久失效。→ **放弃重路由，统一 `captureStream`**（它只是复制信号，不影响播放，也不受元素复用影响）。
2. **媒体未就绪时 `captureStream` 返回 0 轨/静音轨**：在 `play()` 刚触发时调用拿不到数据，稍后重新捕获才有数据。→ 在 `loadedmetadata/canplay/playing` 与 250/700/1500/3000ms 定时器上重试；连接后若 700ms 无数据则自动重捕（最多 3 次），真实静音段落不会无限重连。
3. **重试成功但状态没恢复**：`kind` 在失败时被置为 `none`，重试成功后没有重新按音源标记，导致 `update()` 一直走呼吸值。→ 每次 `connect()` 都按 `el.currentSrc` 重新判定音源类型。

**V1 的两个观感修正（首版“看不到效果”的复盘）**

1. 首版脉冲层挂在 fluid 背景组件里，背景不是「多色动态模糊」时完全没有；现在改为歌词页的**全局层**（`LyricsAudioPulse`），与背景风格解耦。
2. 首版映射用 `power / 255`（真实音乐大多只有 20–80），0.6 强度下级别只有 0.05–0.18，肉眼几乎看不出；现在以 **140 为满强度参考值**归一化，默认强度下级别 0.3–0.6，节拍清晰可见。

**实测数据**

| 场景 | 结果 |
|---|---|
| 缓存歌曲起效时间 | 首曲 ~1.0s，后续切歌 ~0.2s |
| 暂停后 | `active=false`，呼吸值 0–40，背景不再跟节拍 |
| 设置开关「随音乐反应」 | CSS 变量 0.37 → 0 → 0.315（关/开即时生效） |
| 默认强度下的观感 | 脉冲层 0.46–0.60（满值 0.6），播放/暂停截图对比明显；背景关闭时仍可见 |
| 歌词页隐藏 | 运行时 `running=false`，订阅者保留但不空转 |
| 远程音源 | `kind=none` + 呼吸兜底，播放/切歌/进度不受影响 |
| 桌面歌词 / 远程窗 | 不订阅运行时，零额外开销 |
